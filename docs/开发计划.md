## 0. 执行策略

1. **底座优先**：先把能打开、能切换、能存数据的壳子做出来，再往上挂模块。
2. **安全网最先**：数据层和「导出／导入／重置」在阶段 1 就做完。后续每写一个模块都能随时备份，避免开发中途丢数据。
3. **垂直切片**：每个模块一个文件，从数据 → 渲染 → 抽屉表单 → 状态变更一次做完，不横向铺「先写完所有表单再写所有列表」。
4. **每阶段可运行**：任一阶段结束时，双击 `index.html` 都能正常打开，且能跑通该阶段对应的验收条目。
5. **最后按 PRD 逐条打勾**：阶段 5 不新增功能，只做收口和全量验收。

阶段 3 与阶段 4 的六个模块彼此无依赖，可按任意顺序实现。

## 1. 技术选型与理由

| 项 | 选择 | 理由 |
|---|---|---|
| 页面形态 | 单个 `index.html` + 分离的 CSS/JS 文件，传统 `<script src>` 按序加载 | 双击即用，不装环境、不启服务、不构建 |
| 框架 | **不用任何框架**，原生 HTML/CSS/JS | Vite/React/Vue 都需要构建或 dev server，违反 PRD 第 0 章 |
| 模块化 | 全局命名空间 `App.*`，每个文件挂到 `App` 上；**禁止 `import` / `export` / `type="module"`** | `file://` 协议下 ES module 会被 CORS 拦截（见风险 R1） |
| 数据存储 | `localStorage`，单键 `worklife:v1` 存整份 JSON | 数据以文本为主、量小；整读整写与导出/导入的 JSON 天然同构，实现最简 |
| 数据读取 | 不从外部 JSON 文件 `fetch` | `file://` 下 fetch 本地文件会被拦截（R2） |
| 主题 | CSS 变量 + `<html data-theme="dark|light">` | 纯本地、无依赖，刷新后保持 |
| 图标 | 内联 SVG 或 CSS 几何图形 | 不引图标库、不引 CDN、不联网 |
| 字体 | 系统字体栈 | 不引外部字体，离线可用 |
| 路由 | 内存状态 `App.state.page`，不做 URL 路由 | PRD 明确不做返回栈、面包屑、多级页面 |
| 图表 | 手写内联 SVG 迷你折线（仅健身体重趋势） | 不引图表库，PRD 不做复杂图表 |

**明确不引入**：npm 包、构建工具、CDN 资源、外部字体、图表库、日期库、状态管理库、任何服务端代码。

**建议固定存放路径**：`C:\Users\陈子裕\Desktop\3hesx\worklife\`。整个文件夹不要移动或改名（原因见风险 R3），备份靠导出 JSON。

### 3.2 导出文件格式（`PRD.md` 第 7 章）

```
{
  "app": "worklife-local",
  "schemaVersion": 1,
  "exportedAt": "2026-11-12T09:30:00+08:00",
```

### 3.3 状态枚举（集中在 `core.js` 的 `App.enums`，各页只读）

| 用途 | 取值 |
|---|---|
| 选题状态 | `idea` 想法 / `writing` 撰写中 / `ready` 待发 / `published` 已发 |
| 项目状态 | `active` 进行中 / `archived` 已归档 |
| 任务类型 | `task` / `bug` |
| 任务优先级 | `high` / `mid` / `low` |
| 任务状态 | `todo` / `doing` / `done` |
| 游戏状态 | `want` 想玩 / `playing` 在玩 / `done` 通关 / `dropped` 弃坑 |
| 今日事项来源 | `media` / `dev` / `consult` / `fitness` / `diet` / `games` / `manual` |
| 餐次 | `breakfast` / `lunch` / `dinner` / `snack` |

### 3.4 编码约定

- **ID**：`Date.now().toString(36) + Math.random().toString(36).slice(2,7)`。
- **日期**：一律本地 `YYYY-MM-DD` 字符串，用 `getFullYear/getMonth/getDate` 拼接；**禁止 `toISOString().slice(0,10)`**（UTC 偏移会导致跨日错乱，见 R5）。时间用 `HH:mm` 字符串。
- **唯一写入口**：所有数据变更必须走 `App.store.commit(mutator)` —— 修改 state → `save()` → 触发 `change` 事件 → 刷新当前页与首页摘要。任何页面不得直接 `localStorage.setItem`。
- **写入失败**：`save()` 用 try/catch，捕获配额或禁用存储异常时给明确 Toast 并提示立即导出（对应验收 B7）。写入前估算字符串长度，超过 4MB 提前提示导出。
- **渲染**：每个页面导出 `App.register('media', { title, desc, primaryAction, render(container), todayCandidates() })`；事件用委托绑定在容器上。
- **不整页重渲染输入框**：行内编辑只更新对应 DOM 节点；抽屉打开期间不重建抽屉（见 R6）。
- **文本安全**：用户输入一律用 `textContent` 或转义后再插入，不拼接 `innerHTML`（见 R7）。
- **删除**：单条统一走 `App.ui.undo(label, fn)` → 立即移除 + Toast「已删除 · 撤销」；级联/清空/导入覆盖/重置走 `App.ui.confirm({ title, body, requireText })`。
- **空状态**：每个列表统一 `App.ui.empty({ text, actionLabel, onAction })`，不显示空白或 0。
- **主题**：`document.documentElement.dataset.theme`，切换后写入 settings 并触发 `commit`。

2. **持久化**：按 A2 → A3 → A4 顺序做（刷新 → 关浏览器 → 重启电脑），每步确认数据仍在。这一步要真的重启一次，不能只刷新。
3. **备份**：B 组用两个不同的备份文件做「改动 → 导入旧备份 → 恢复」的往返；B3 必须验证「取消」后数据一条不变。
4. **联动**：C4 专门验证快照语义——加入今天后删除源条目，今日计划那条必须还在。
5. **模块主流程**：D 组每个模块跑通一条完整链路（新建 → 编辑/改状态 → 记录 → 回显），不是只看页面能打开。

## 7. 风险与应对

| 编号 | 风险 | 应对 |
|---|---|---|
| R1 | `file://` 下 ES module 被 CORS 拦截，页面白屏 | 全程传统 `<script src>` + `App.*` 全局命名空间，禁用 `import`/`export`/`type="module"`；阶段 0.7 就验证一次 |
| R2 | `file://` 下 `fetch` 本地 JSON 失败 | 不 fetch；所有数据只在 `localStorage` 与内存 state 之间流转 |
| R3 | `file://` 的本地存储与文件路径绑定，**移动或重命名文件夹后旧数据读不到** | 固定存放路径写进 `README.md` 与存储说明；明确导出 JSON 是唯一可迁移备份；开发期不做自动迁移（超出第一版范围） |
| R4 | `localStorage` 约 5MB 上限 | 单键存整份 JSON；`commit` 前估算长度，超 4MB 提示导出；个人文本数据足够，不做 IndexedDB |
| R5 | `toISOString()` 按 UTC 转换，导致凌晨记录算到前一天 | 统一 `todayStr()` 用本地年月日拼接；所有日期字段用 `YYYY-MM-DD` 字符串比较，不用 Date 对象比较 |
| R6 | 整页重渲染导致输入框失焦、抽屉被重建、光标跳走 | 行内编辑只更新对应节点；抽屉打开期间不触发整页 `render()`；事件委托绑定在容器上 |
| R7 | 用 `innerHTML` 拼接用户输入，内容里的 `<` 破坏 DOM | 一律 `textContent` 或转义；`escapeHtml()` 集中提供 |
| R8 | 导入不同版本或无关 JSON 导致数据被静默覆盖 | 校验 `app === 'worklife-local'` 与 `schemaVersion`；未知版本拒绝并提示，不写入 |
| R9 | 无痕模式或禁用本地存储时写入失败无感知 | `save()` try/catch，失败给明确 Toast 并提示立即导出（对应 B7） |
| R10 | 开发中顺手加搜索、拖拽、提醒等 | 每阶段结束对照 `PRD.md` 第 9 章复查一次；见第 8 章边界纪律 |
| R11 | 首页摘要与各模块字段对不上，数字不刷新 | 指标计算集中在 `page-home.js` 的 `summaries`，所有变更统一走 `commit` 触发 `change` 刷新；C1 专门验收 |

## 8. 边界纪律

- **不引依赖**：不装包、不构建、不引 CDN、不写 `localhost` 服务、不写任何后端代码。
- **不顺手加功能**：任何 `PRD.md` 第 9 章之外的想法，先按 PRD 的「变更约定」更新 PRD 并说明原因，再决定是否实现；不更新就不做。
- **不留半成品**：代码里不留「先放个 TODO 以后接」的入口；要么做完，要么不做。
- **每阶段收尾对照**：阶段完成判定之外，额外对一次第 9 章，确认范围没有膨胀。
